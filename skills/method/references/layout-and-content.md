# 横向布局与信息密度

## 公开示例如何使用

先看 [GRPO 方法图](../assets/grpo/method.png) 和 [Transformer 方法图](../assets/transformer/method.png)。GRPO 示例展示紧凑策略条目、同行评分与验证、共享优势及分层目标函数；Transformer 示例展示横向架构、残差支路、因果矩阵、注意力操作和并行 head 汇合。

需要检查元素属性时读取各目录中的 method.excalidraw；论文依据与素材来源见 [public-examples.md](public-examples.md)。比较两图中的不同公式尺寸：只根据视觉比例调整偏大的具体公式，不固定缩放因子，不将所有公式统一缩小。图标数量与画布压缩量不是通用指标。

## 尺度起点

以下为约 1500 px 宽画布的设计坐标，不是印刷字号。

| 对象 | 建议 |
|---|---|
| 总标题 | 28–34 |
| 阶段标题 | 23–27 |
| 子模块标题与实体名称 | 21–25 |
| 机制短说明 | 17–20，优先保持不低于 16 |
| 主实体图标 | 44–64，复杂主体可更大 |
| 书本、笔记、清单 | 36–48，细节应可辨认 |
| 火焰/雪花等状态角标 | 18–26，避免与主体同级 |
| 主边框 | 深灰，strokeWidth 2–2.2，roughness 约 1.1–1.4 |
| 填充小框 | hachure 起点 roughness=1、strokeWidth=1 |
| 图文安全间距 | 6–10，按完整边界判断 |
| 模块间距 | 通常 12–24，跨阶段连线按实际需要留槽 |

缩到 ACL 双栏通栏宽度后检查最小文字，必要时简化标签、重新排版。不要只凭原画布上看得清认定可投稿。黑白灰组件承托原色图标，不将所有图片去色；淡米色、淡绿或淡蓝子模块背景只用于分组。保持正文和公式清楚，手绘感主要由线条、框和填充表达。

## 增加有用信息

以“对象—操作—信号—更新/输出”检查已有机制，补图中有根据却未表达清楚的关系。例如参考本身包含：
- 同一问题采样多个回答：可说明组内奖励如何形成相对优势。
- 裁剪代理目标和参考 KL：可分别标明限制更新激励与约束行为偏移的作用。
- 多头注意力：可明确不同投影、并行计算与拼接汇合。
- 两种联合损失：分别标出其学习作用，不添加参考中未出现的正则项。
- 条件控制退出某阶段：如果语义明确，可标出不满足条件时继续原训练；若真假分支不明，不自行确定。

这些例子不是待复制文案。只解释参考支持的含义；不要猜测奖励实现、优势估计公式、阈值定义、参数共享或停止条件。

## 收紧布局

优先找宽标题栏、孤立标签、等高容器留下的空白。短标签与实体放在一起；把宽而低的内容并置，将子模块底部空间用于本模块解释。分组留白和连线通道保留，去掉装饰性重复标题、无依据的图标与复述段落。机制过多时适当增加高度比统一缩小字体更好。

连线区分数据流、梯度/更新和控制流，并提供必要图例；反馈只在算法有该关系时绘制。颜色含义保持一致，图标与箭头不能覆盖公式或实体名称。嵌套容器不算碰撞，手持书本与机器人可有意组合，但整个文本矩形不得被图片遮住。


## 一体化与充实内容同时实现

- 去掉显眼的步骤数字、编号徽章和不必要的重复对象编号；保留有科学含义的轨迹索引、公式下标与数据值，不能把它们当装饰编号删去。
- 优先让对象、操作和结果共享视觉行或局部区域。GRPO 中“回答 → 奖励与核验结果”的同行布局同时减少重复与空白，比两个独立等高列表更紧凑。其他任务依实际对应关系组织，不能错误合并数据或改变分支。
- 先拆除造成留白的层层外框，再压缩容器。整体可以有一个轻边界，内部仅为不同目标、注意力计算、评分等需要分组的内容保留小框。不要把“统一”理解为消除所有层级。
- 补充解释要提升机制理解。例如参考支持时，可说明组内奖励与共享优势的关系、参考策略与旧策略的不同职责、因果遮罩如何控制可见性。不要给每张图强加这些内容。
- 在公式上下、模块下缘或连接处放短说明；留白不适合容纳文字时改布局。内容增加后保留主体字号，不恢复先前冗余标题栏或大卡片。允许少量增高，避免内容紧贴边框。
- 回路线沿模块间通道走，用清晰折线避免平滑曲线大幅外凸。检查箭头起止点和完整路径；不能把更新箭头落到标题文字上，也不能只凭图文碰撞报告判断连线安全。
- 改完同时看整体与密集局部：正文、公式、图标无意外遮挡，所有必要分支仍清楚；内容丰富不能以牺牲已确认的紧凑、一体化风格为代价。


## 公式比例与局部密度

以全图为单位检查视觉层级，再逐条决定公式大小。公式的宽度取决于字符数量，分式高度还包含上下结构；不要强行让所有公式同宽、同高，也不要因为一条公式偏大就等比例缩小所有公式。避免大求和符号、长 KL 展开式或注意力主公式成为整张图最抢眼的部分。普通 FFN、归一化公式、优势公式与策略符号是否需要调整，应依据实际成图判断，不按名称预设。

修改前记录待调整元素的 ID 和尺寸；只改变选中的公式图片，保持宽高比，根据其容器居中或对齐。源 LaTeX 和科学内容不变。先前一次性缩小全部公式不符合用户意图时，从备份恢复未指定公式的原尺寸，再进行局部调整。不要将某次使用的缩放比例固化成通用参数。

缩小公式后收紧对应行高、相邻说明和下方组件间距，不留下新的大空洞；无关模块无需一起缩放。最终在整体预览与论文通栏尺寸下分别检查：公式没有喧宾夺主，分子、分母、上下标仍清楚，图标和标题无重叠。图文碰撞检查之外还要检查文字与文字、连接线与文字的相交。

## 用机制细节填补空白

- 模型卡片只有图标、名称和符号时，可改为低矮横向条目，将状态与具体职责放在同一区域；不靠放大机器人或公式填满卡片。
- 评分区将回答、奖励、核验图标同排显示；符号应与真实判断一致。把单一结果优势广播给多个 token 时，明确这是一条回答的共享优势，不伪装成独立 token 奖励。
- 公式较复杂时，可配“整体目标 + 局部操作”的结构。原生裁剪区间只解释代理目标的 clip，不能暗示实际参数变化被硬限制；注意力的可见性矩阵不是实测注意力权重。
- 并行分支应通过真实连线汇合；多头示意不能只把最后一个 head 接到拼接节点。抽样画少数分支时保留省略含义，不误报实际数量。
- 配图标与原生小图的目的都是说明机制。信息量、图标数量和紧凑度共同评估，不以固定图标数、翻倍或画布压缩百分比作为完成指标。
